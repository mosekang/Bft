# ADR-0003 — Phase 2 런 규칙 구현 결정과 밸런스 결과

상태: 채택(전체 Phase 자동 승인) · 날짜: 2026-09-26

`packages/engine/src/run/*`(런 규칙, `applyAction`, `advance`), `bots/`(원형 8종), `arena.ts`(`bot-arena`)가 §4, §7~§11, §15를 구현하면서 정한 것.

## 구현 결정

| # | 항목 | 결정 | 근거 |
|---|---|---|---|
| 1 | **상태 확장** | `PlayerState`에 `augmentOffer, choice, tradesLeft, ready, rerollCount, stadiumPicked, idleRounds, benchBonus, scoutingActive, lastResult, lastIncome`, `GameState`에 `roundIndex, nextInstanceId, carousel, createdAt`, `Matchup`에 `names, kind, winner, game`. `Phase`에 `STADIUM`, 액션에 `PICK_CHOICE{idx}` 추가. | §13은 최소 골격만 정한다. 선택지(올스타 부품 3택1, 프랜차이즈 ★★ 카드, 레전드 특수 아이템)를 처리할 액션이 없었다. |
| 2 | **난수 스트림** | `roundRng(state, label) = createRng(seed).fork("r{roundIndex}").fork(label)`. 상점은 `shop:{player}:deal / reroll{n}`, 경기는 `{seed}:{round}:{match}:{game}`. RNG 상태를 저장하지 않고 카운터로 재현. | §6.6 시드 트리. 리롤 횟수만 저장하면 세이브/리플레이가 단순해진다. |
| 3 | **상점 카드와 풀** | 상점에 나가 있는 카드는 풀에서 빠져 있고 리롤·탈락 시 돌아온다. 카러셀 카드도 생성 시 풀에서 뺀다. | §4.4 "내가 사면 남의 상점에서 사라진다"를 정합적으로 만드는 가장 단순한 모델. 테스트: 풀 + 소유 + 상점 + 남은 카러셀 = 상수. |
| 4 | **벤치 가득 찰 때 구매** | 합성이 완성되는 카드는 벤치가 꽉 차도 구매 가능(TFT 규칙). 카러셀은 가장 싼 벤치 카드를 자동 판매(§10.1). | |
| 5 | **합성 시 유지 카드** | 보드 위 사본을 우선 유지, 아이템은 최대 3개까지 승계하고 초과분은 인벤토리로. 성장치는 최댓값 승계. | §4.5 |
| 6 | **트레이드 마감** | `TRADE{cardInstanceId, offerIdx}` 한 번에 실행. 제시 3장은 `trade:{player}:{card}` 스트림으로 결정적이라 UI가 미리 보여줄 수 있다(`tradeOffersFor`). 교환된 카드는 같은 별 등급으로 풀에서 가져오고, 원래 칸(보드/벤치)에 놓인다. | §10.2 |
| 7 | **x-1 라운드** | FA 시장 후 같은 라운드에 PvP 경기(ADR-0001 유지). | |
| 8 | **한국시리즈** | 2팀 남으면 한 라운드에서 최대 3경기. 시리즈 패자는 hp 전부를 잃어 탈락, 승자는 데미지 0. 게임당 데미지 합산 ×2는 `lossDamage(stage 7)`이 이미 ×2. | §10.3 |
| 9 | **고스트 상대** | 홀수 생존 시 가장 최근 탈락자의 마지막 보드(피로 0). 탈락자 `PlayerState`를 지우지 않아 스냅샷 역할. 탈락자가 없으면 훈련팀. | §10.3 |
| 10 | **PvE 팀** | 훈련팀: 전 내부치 40. 레전드: 전 내부치 80(★★ 보정 포함 가정). 올스타: 풀에서 OVR 상위 카드 `level+1`장으로 임시 보드. | §4.1, §10.2 |
| 11 | **ABS(양 팀)** | 한쪽만 ABS여도 그 경기 양 팀 프레이밍 무효. | §9 |
| 12 | **효과 매핑** | 아이템의 표시치 가산(파워 +10 등)은 내부치로 분배: 파워→hrRate·xbhRate, 스피드→speed·sbSkill, 수비→def·arm, 선구→bbRate, 제구→bbRate(투수), 구위→kRate·contactVs, 무브먼트→hrRate·gbRate. `OF_COMMANDER`의 "담당 뜬공 BABIP −.03"은 def +25로 환산. `IRON_WALL`의 "대체선수 옆 칸 +5"는 미구현(효과 미미). | §8 |
| 13 | **봇의 배치** | 봇은 구매·판매·리롤·XP·장착을 액션 API로 하되, 배치는 `arrangeBoard()`가 합법 보드를 직접 산출(레벨 상한·역할 검사 동일). | §11.2-5 "탐욕 배정". MOVE 액션 수십 개로 쪼개는 것과 결과가 같다. |

### 미해결 / 후속
- **무승부 비율**: ADR-0002 #6. 목표를 1~4%로 낮추거나 연장 10회로 줄이는 결정 필요.
- **5코스트 ★★ 0.26**: 사양 수치(풀 10장, 상점 확률)를 건드리지 않고 봇 행동만으로는 0.2~0.27. 후보: `POOL_COPIES[5]` 10→12, 또는 6-1 FA 최종 시장에 5코스트 비중↑. Phase 6 재검증 때 결정.
- **유망주팀 3.55**: 편차는 범위 안이지만 여전히 최강 원형. 성장 규칙 자체가 강하다는 신호로 Phase 6에서 재확인.
- `IRON_WALL` 인접 칸 수비 +5 미구현.
